# Paint Pro — WPF + SkiaSharp

Растровый графический редактор в стиле Apple Liquid Glass (iOS 26 / macOS Tahoe 26).
Перенос Electron-версии на C# 12 + WPF + SkiaSharp.

## Что внутри

- `src/PaintPro.Wpf/` — основной WPF-проект
  - `Models/` — `Document`, `Layer`, `Selection`, `FloatingPickup`, `DocumentMode`, `ToolKind`
  - `Commands/` — Command Pattern: `DrawStrokeCommand`, `FillCommand`, `EraseRegionCommand`,
    `RegionDiffCommand`, `ClearCanvasCommand`, `ResizeCanvasCommand`, `PasteCommand`,
    `LayerStackCommand` (добавление / удаление слоя),
    `ReplaceAllLayersCommand` + `DocumentTransform` (поворот / отражение / кадрирование),
    `LayerPropertyCommand` (видимость / прозрачность слоя),
    `LayerTarget` (привязка команды к конкретному слою)
  - `Tools/` — `ITool` + 18 реализаций (Pencil, Brush, Marker, Eraser, Fill, Picker, Text,
    Line, Rect, Ellipse, Triangle, Star, Arrow, Heart, Select, Quad, Crop, Hand)
  - `Services/` — `HistoryManager`, `FileService`, `ClipboardService`, `GeometryMath`,
    `BitmapKeying`, `PickupOps` (подъём пикселей, ленивое стирание, сдвиг объекта
    вместе с его маской и попадание мыши в повёрнутый объект), `SkiaBitmapBridge`
  - `ViewModels/` — `MainViewModel`, `ColorEntryViewModel`
  - `Views/` — `CanvasView` (SkiaSharp + overlay), `PromptDialog`. Сборку документа
    (слои + превью инструмента + плавающий объект) держит `Document.Render` — одна и та
    же для экрана и для сохраняемого файла. По ней же выверена `Document.SampleComposite`
    (пипетка и статусбар): всё, что показывает пользователю цвет, обязано брать его из
    одной и той же картинки
  - `Resources/` — `Themes.xaml`, `GlassStyles.xaml`, `ToolIcons.xaml`
- `tests/PaintPro.Tests/` — xUnit, 464 теста. Каждый файл — разбор одного релиза, и
  каждый тест назван тем, что он защищает, а не тем, что он вызывает. Отдельно стоят два
  фаззера: `TimelineFuzzTests` — случайные последовательности правок по seed'у (двадцать
  пять видов) и четыре инварианта ленты истории поверх них, самый сильный из них «позиция
  курсора однозначно задаёт документ, каким бы путём до неё ни дошли»; и
  `DirtyFlagFuzzTests` — односторонний закон «картинка отличается от сохранённой ⇒
  документ изменён» плюс точечная проверка, что пустой жест документ не пачкает
- `tools/generate-icon.ps1` — генератор многоразрешённого `.ico` (16/32/48/64/128/256)
- `dist/PaintPro.exe` — финальный self-contained single-file билд (~78 МБ)
- `paint-pro-electron/` — исходная Electron-версия, живёт параллельно и
  поддерживается. Её устройство и грабли: `paint-pro-electron/README.md` и
  `paint-pro-electron/DEV_CONTEXT.md`. Историю обеих версий ведёт общий
  `CHANGELOG.md`; C#-версия — 1.20.0, Electron-версия — 1.11.0 (правки 1.12.0—1.20.0
  касаются только C#-стороны).

## Запуск из исходников

```pwsh
cd src/PaintPro.Wpf
dotnet run -c Release
```

Требует **.NET 8 SDK**. Релизный билд — `dotnet build -c Release`.

## Тесты

```pwsh
dotnet test tests/PaintPro.Tests/PaintPro.Tests.csproj
```

`MainViewModel` в тестах конструируется без диспетчера WPF — через него проверяется весь
слой команд (Undo/Redo/Paste/Delete/смена инструмента), который иначе не покрыт. Не
вызывать оттуда только то, что открывает модальное окно: `NewDocument`/`Open` при
изменённом документе, `ResizeCanvas`, `PickCustomColor` — логику из них выносить в
методы без диалога (так сделаны `MainViewModel.TryParseCanvasSize` и
`MainViewModel.ResetDocument`). Системный буфер обмена из тестов тоже недоступен: он
работает только из STA-потока, а прогон идёт в MTA — то, что не про сам буфер,
проверяется через `ClipboardService.ExtractForClipboard` (он возвращает null, когда
копировать нечего).

## Сборка финального .exe

```pwsh
cd src/PaintPro.Wpf
dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -o ../../dist
```

На выходе — `dist/PaintPro.exe` (~78 МБ, single file, всё внутри).
Для portable-сборки без runtime: убрать `--self-contained true` → ~5 МБ, но нужен .NET 8 Desktop Runtime.

## Установщик

Inno Setup 6, скрипт — `installer/PaintPro.iss`. Упаковывает готовый
`dist/PaintPro.exe`, поэтому publish должен пройти первым.

```pwsh
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\PaintPro.iss
```

На выходе — `dist/PaintPro-Setup-<версия>.exe`. Версия задаётся в двух местах и
должна совпадать: `MyAppVersion` в `.iss` и `<Version>` в `PaintPro.Wpf.csproj`.

Оба каталога `dist/` в `.gitignore` — бинарники не коммитятся.

## Архитектура

См. `REWRITE_PROMPT_CSHARP.md` для полной спеки и обоснования каждого решения
(включая 7 антипаттернов из Electron-версии и как они адресованы в C#).

### Ключевые инварианты

1. **`Selection` ⊕ `FloatingPickup`** — взаимоисключающие. Property-setter
   автоматически коммитит/сбрасывает другой. (см. `Document.cs`)
2. **`ClearCanvasCommand`** сбрасывает все state-слои — не только bitmap, но и
   selection/floating/mode. (антипаттерн §1) И все слои документа, а не активный:
   `Flatten` складывает их все, поэтому «чистый» холст с содержимым на верхнем
   слое уходил бы в файл при следующем Ctrl+S. Поднятое выделение возвращается на
   холст до снимка, а не сохраняется в самой команде: иначе отмена давала холст с
   дырой, а битмапы пикапа не освобождались вовсе, если запись вытесняло
   переполнение истории. От стопки при этом остаётся один слой — бумага: новый
   документ это чистый лист, а не старый со стёртым рисунком, и панель слоёв после
   «Создать» не должна показывать прежние «Layer 1», «Layer 2». Отмена собирает стопку
   обратно с прежними `Layer.Id`, иначе записи истории, сделанные до очистки,
   перестали бы находить свою цель (инвариант 8).
3. **Handles скрываются на время drawing** через `ToolContext.IsDrawing`.
   (антипаттерн §2)
4. **Хоткеи живут на Window.InputBindings**, кнопки — `Focusable="False"`.
   (антипаттерн §3)
5. **Undo через Command Pattern с diff-bitmap**, не PNG-snapshot всего canvas.
   (антипаттерн §5)
6. **Polygon lazy-erase** при первом translate/scale/rotate, по форме
   полигона а не bbox. (антипаттерн §6). Единственная реализация —
   `PickupOps.EnsureLazyErase`, ей пользуются и SelectTool, и QuadTool, и ручки на канвасе.
   Стирается форма **на момент подъёма** (`FloatingPickup.OriginalQuad` заполняется в
   `PickupOps.Promote`), а не та, что на пикапе сейчас: перетаскивание угла меняет маску,
   но не то, что было взято из слоя. Пока снимок делался при первом перемещении, углы,
   уведённые до него, подменяли форму — в слое пробивалась дыра там, где пользователь
   ничего не выделял, а часть выделенного оставалась лежать на месте.
7. **Один `DocumentMode` enum**, не куча bool-флагов. (антипаттерн §7).
   `Cropping` и `DrawingShape` задаёт инструмент, `RecomputeMode` их не перетирает.
8. **Команда привязана к слою, а не к «активному сейчас»** — `Layer.Id` переживает
   пересоздание слоя (resize / rotate / crop), команды резолвят его через
   `LayerTarget`. Если слой удалён, undo просто ничего не делает вместо записи
   пикселей в чужой слой.
9. **Операции над документом трогают все слои сразу** — `DocumentTransform` строит
   один `ReplaceAllLayersCommand`. Иначе `CanvasWidth` рассинхронизируется
   с размерами неактивных слоёв.
10. **`Push` игнорируется, пока история применяется** (`HistoryManager.IsApplying`).
    `CommitFloating` умеет писать в историю, и без этого флага вызов изнутри
    `Undo`/`Redo`/`JumpTo` резал список под идущим по нему курсором.
11. **Escape возвращает поднятые пиксели** (`Document.CancelFloating`), Delete
    оставляет дыру, но пишет её в историю (`Document.DiscardFloating`), Enter
    применяет. В Electron-версии Escape раньше тоже применял, то есть отказаться
    от подъёма было нечем. `DiscardFloating` и `CommitFloating` сами доводят до конца
    ленивое стирание: подъём исходную область не трогает, и без этого Delete и Ctrl+X
    по только что поднятому выделению возвращали пиксели на место — «вырезал, а ничего
    не вырезалось».
12. **Прозрачность применяется один раз, при слиянии** — инструменты рисуют штрих
    непрозрачным в свой буфер, альфа уходит в `DrawStrokeCommand`. Иначе
    перекрытия сегментов внутри одного штриха темнеют. В Electron-версии то же
    самое делают `beginPreviewStroke` / `mergePreviewStroke`, и там у правила есть
    вторая половина: `ctx.globalAlpha` обязан быть равен 1 вне пар
    `save`/`restore`. `globalAlpha` — состояние контекста, а не операции, и
    инструмент, оставивший его на 0.4, портит следующие отмену, очистку и поворот.
13. **Стирание вверх по стеку слоёв идёт в прозрачность, а не в белое** —
    `PickupOps.EraseColor` для выделений, `SKBlendMode.DstOut` при слиянии штриха
    ластика. Белым заливается только нижний слой: он и есть бумага документа.
14. **Всё, что видит пользователь, читается с композита, а не с активного слоя** —
    `Document.SampleComposite` для пипетки и статусбара, `FileService.Flatten`
    для копирования в буфер. Композит включает и плавающий объект, и на своём месте в
    стопке — том же, куда его кладёт `Document.Render`, с поворотом, quad-маской,
    растяжением и прозрачностью слоя. Пока выборка складывала одни слои, пипетка
    отвечала цветом того, что лежит ПОД вставленной картинкой: на экране синее, в
    палитре белое. Курсор ушёл с холста — гаснут и координаты, и цвет: оставшийся HEX
    читается как текущий. Проверяется это сравнением с самой отрисовкой, а не ожидаемым
    числом (`CompositeSamplingAndPreviewTests`).
15. **Цель Ctrl+S переустанавливается при каждой смене документа** —
    открытие файла делает целью его (`FileService.OpenImage` обнуляет
    `LastSavedPath`), «Файл → Создать» отвязывает документ вовсе
    (`FileService.Detach`). Иначе `SaveOrSaveAs` берёт `LastSavedPath ??
    LastOpenedPath` и молча пишет в картинку, к которой документ уже не имеет
    отношения.
16. **История ограничена и по глубине, и по памяти** — `MaxDepth` и `MaxBytes`.
    Команды сообщают свой вес через `IDocumentCommand.ApproximateBytes`; поворот
    большого документа держит два полных битмапа, и одной глубины тут мало.
    Выброшенная запись освобождается явно: команды с пикселями реализуют
    `IDisposable`, и `HistoryManager` зовёт его при обрезке, при срезании хвоста
    повтора и при `Clear`. Битмапы Skia лежат в нативной памяти, давления на
    сборщик не создают, и без этого лимит по байтам ничего не освобождал.
17. **Обработка мыши только для левой кнопки** — `MouseDown` в WPF приходит для
    любой, без проверки правый клик запускал активный инструмент. В
    Electron-версии то же самое верно для `mousedown` на `<canvas>`.
18. **Закрытие окна спрашивает про несохранённое** — `MainViewModel.IsDirty`
    сравнивает позицию в истории с той, что была при последнем сохранении, поэтому
    откат к сохранённому состоянию считается чистым. Открытие файла эту метку
    двигает: только что открытая картинка — не несохранённая работа. Сама метка
    живёт внутри `HistoryManager` (`MarkSaved` / `IsDirtySinceSave`), потому что
    там же вытесняются старые записи и сдвигается курсор: копия снаружи об этом не
    узнавала, и после переполнения истории документ навсегда считался чистым. В
    Electron-версии то же самое считает `isDirty()` в renderer (метка едет в
    `saveHistory`), а диалог по `close` показывает main. Метка, оставшаяся в
    срезаемом хвосте повтора, уходит в недостижимое значение: после «сохранили →
    Ctrl+Z → нарисовали заново» курсор встаёт на то же число, и одинаковый номер
    означал бы сохранённым другой документ.
19. **Сохранение сначала фиксирует всё незакоммиченное** — плавающий пикап и
    открытый текстовый редактор. Иначе в файл уходит документ без того, что
    пользователь на нём видит, а цель Ctrl+S при этом уже указывает на открытый
    файл.
20. **Маска пикапа живёт в неповёрнутых координатах его габарита** — и хранится так, и
    пересчитывается так (`FloatingPickup.ApplyResize`). Поворот накладывает уже
    рисование: `Document.DrawPickup` крутит канву и только потом режет по маске, а
    `PickupOps.ToLocal` снимает поворот с мыши перед сравнением. Значит какие пиксели
    останутся под маской, решает её положение ОТНОСИТЕЛЬНО габарита — доли по ширине и
    высоте, — и масштабирование обязано сохранять именно их. Пересчёт вокруг мировой,
    то есть уже повёрнутой, позиции якоря смешивает две системы координат: пока пикап
    не повёрнут, ошибка равна нулю, а после поворота маска уезжает с первого движения.
21. **Смена геометрии холста снимает выделение** — внутри самих команд
    (`ResizeCanvasCommand`, `ReplaceAllLayersCommand`), а не в вызывающем коде.
    Координаты рамки после поворота или обрезки указывают уже не на то, что
    выделяли, и делать это в команде — единственный способ, работающий и при
    откате по истории.
22. **Действие, не изменившее ни пикселя, не пишется в историю** — подъём
    выделения, положенный обратно без сдвига; заливка области, уже залитой этим
    цветом; штрих, фигура и текст с нулевой прозрачностью; текст из одних пробелов;
    смена размера холста на тот же самый. Пустая запись не только мусор в списке:
    `IsDirty` считается по позиции
    курсора, и приложение начинает спрашивать про сохранение после ничего. Признак
    берётся из результата операции (`FillCommand.ChangedAnything`, сравнение
    геометрии пикапа), а не из факта вызова обработчика. По той же причине сам по
    себе поднятый пикап не считается несохранённой работой: и `IsDirty`, и
    `CommitFloating` смотрят на `FloatingPickup.HasMoved` — сравнение текущей геометрии
    со снятой при подъёме. Именно сравнение, а не флаг «что-то делали»: стирание
    исходной области идёт по началу жеста, и нажатие на ручку без перетаскивания
    объявляло документ изменённым, а коммит писал пустую запись «Перемещение». В
    Electron это `floatingMoved()`.
23. **Размер холста ограничен сверху** — `ResizeCanvasCommand.MaxDimension` и
    `MaxPixels`, те же значения в Electron. Буфер на 10 миллиардов пикселей не
    выделяется, но `canvas.width` об этом не сообщает: холст молча становится
    нерисуемым вместе со всем, что на нём было.
24. **Версия в интерфейсе читается из сборки** (`MainViewModel.AppVersion`), в
    Electron — из `package.json` через `app.getVersion()`. Вписанная руками строка
    в статусбаре и в «О программе» отставала на шесть релизов.
25. **Открытие файла заменяет документ целиком** — `DocumentTransform.OpenImage`
    ставит картинку на нижний слой, очищает верхние и меняет размер холста одной
    `ReplaceAllLayersCommand`. «Сменить размер и нарисовать в активный слой» тут не
    годится: смена размера переносит содержимое всех слоёв, и старый рисунок
    остаётся лежать поверх открытой фотографии — в том числе в сохраняемом файле.
26. **Захват мыши берёт элемент, который не пересоздаётся** — ручки живут на
    `Overlay`, а `DrawOverlay` каждый кадр чистит его детей. WPF снимает захват с
    элемента, убранного из дерева, поэтому `CaptureMouse` зовётся на самом
    `Overlay`, и он же слушает `MouseMove`/`MouseUp` жеста. Захват при этом может
    уйти и сам - чужое окно вышло вперёд, Alt+Tab, модальный диалог, - поэтому и
    `Overlay`, и `SKElement` слушают `LostMouseCapture` и завершают жест по
    последней известной позиции. Иначе `MouseUp` не приходит вовсе: штрих не
    попадает в слой и пропадает вместе с превью.
27. **Ошибка ввода-вывода доезжает до пользователя** — в Electron это значит, что
    обработчик в main возвращает `{ error }`, а не даёт `invoke` отклониться:
    renderer ждёт результат, и необработанное отклонение выглядит как «нажал
    Открыть, ничего не произошло». В WPF то же самое означает, что отказ отличается
    от отмены значением, а не общим null: `SKBitmap.Decode` возвращает null и на
    удалённый файл, и на папку, и на битые байты, поэтому открытие отдаёт
    `OpenOutcome` со статусом.

28. **Поднятое выделение снимается перед любым ходом по истории** —
    `HistoryManager` зовёт `Document.CancelFloating` в `Undo`, `Redo` и `JumpTo`.
    Пикап держит снимок слоя на момент подъёма; после отката этот снимок относится
    к состоянию, которого больше нет, и коммит записал бы в историю diff со старыми
    пикселями, воскрешая отменённое. Первый Ctrl+Z поэтому отменяет сам подъём: это
    правка, которой в списке ещё нет. В Electron-версии то же самое делает
    `restoreHistory`.
29. **Состояние, влияющее на файл, живёт в истории** — видимость и прозрачность слоя
    идут через `LayerPropertyCommand`, а не пишутся в модель напрямую. `Flatten`
    пропускает невидимые слои и учитывает прозрачность, а признак несохранённой
    работы считается по позиции в истории и правки мимо неё не видит. Подряд идущие
    правки одного слоя склеиваются в одну запись (`MergeInto`): ползунок шлёт
    значение на каждый пиксель перетаскивания. Склейка обязана сообщить об этом
    истории (`HistoryManager.AmendCurrent`): курсор при ней не двигается, и без
    этого правка, дописанная в запись, сделанную до сохранения, оставляла документ
    «чистым» — окно закрывалось молча. Склеивается только жест ползунка (одно
    свойство, соседние по времени правки); флажок видимости — отдельное нажатие и
    всегда отдельная запись.
30. **Замена документа спрашивает про несохранённую работу** — `ConfirmDiscard` в
    «Создать» и «Открыть». Обе команды сдвигают метку сохранения, поэтому вопроса
    при закрытии окна после них уже не будет: спросить можно только до.
31. **Инструменты пишут только в видимый слой** — единственная проверка живёт в
    `ToolContext.DrawTarget()`, через неё идут кисти, фигуры, заливка, текст, стирание,
    подъём выделения и вставка. Слой с прозрачностью в ноль отсеивается там же и по той
    же причине: ползунок в панели начинается с нуля, и это тот же скрытый слой, только
    другой дорогой. Штрих по скрытому слою уходил в его битмап целиком: на экране не
    появлялось ничего, в истории появлялась запись, а нарисованное всплывало в файле,
    стоило слой включить. Подъём — та же история наоборот: пикап рисуется поверх
    документа всегда, и пиксели скрытого слоя всплывали на экране, а после прижатия
    исчезали обратно. Вставка (с 1.14.0) — тот же случай: картинка была видна, пока её
    двигали, и пропадала на прижатии, оставив в истории запись. Отказ не молчит —
    причина уходит в статусбар через `ToolContext.ReportHint`.
32. **Буфер обмена берётся с повторами** — `ClipboardService.Retry`. Буфер в
    Windows захватывается монопольно, и пока его держит чужое приложение, вызов
    падает с `COMException`; для обычного Ctrl+C это норма, а не сбой. Отказ после
    всех попыток виден в статусбаре, а Ctrl+X при неудавшейся копии не вырезает:
    иначе пиксели пропали бы в никуда.
33. **Асинхронное восстановление истории запирает холст** — в Electron кадр
    истории грузится через `img.onload`, и между Ctrl+Z и появлением картинки на
    холсте лежит состояние ДО отмены. `state.restoring` не даёт начать штрих в это
    окно, а `saveCanvas` ждёт `restorePending`, иначе Ctrl+S сразу после Ctrl+Z
    записывал бы в файл отменённое. В WPF отмена синхронная, и вопроса не возникает.
34. **Пикап, созданный командой, снимает та же команда** —
    `FloatingPickup.Owner`. Первый Ctrl+Z по обычному подъёму отменяет сам
    подъём и курсор не двигает (инвариант 28), но у вставки пикап и есть эффект записи,
    которая уже лежит в списке: снятый отдельно, он убирал картинку с холста, оставляя
    «Вставку» текущей — история говорила, что вставка применена, а Ctrl+Y её не
    возвращал, потому что курсору было некуда двигаться.
35. **Фон при подъёме выкусывается от краёв внутрь и только там, где он фон** —
    `BitmapKeying.KeyOutBackground` заливает прозрачностью от рамки пикапа и
    останавливается на первом непохожем пикселе. Проход «все белые подряд» проще, но
    пробивает дыры в самой картинке — блик на фото, белая заливка фигуры, глаз на
    рисунке, — и сквозь них видно то, что лежит ниже. В Electron это `keyOutWhite`, и
    там так с самого начала. Зовётся он (с 1.14.0) только для прямоугольного выделения
    с нижнего слоя — по тому же правилу, по которому `PickupOps.EraseColor` возвращает
    бумагу белой: бумага есть только у нижнего слоя, на верхних фон — это пустота, а
    белое там нарисовано. Многоугольнику форму задаёт его собственная маска, и заливка
    ему только вредила: углы габарита лежат вне фигуры, белое снаружи соединено с белым
    внутри, и выкусывалось всё разом.
36. **Область, вырезаемая при фиксации фигуры, покрывает то, что фигура рисует** —
    `ShapeTool.Overshoot`. Габарит жеста и габарит фигуры — разные вещи: наконечник
    стрелки стоит поперёк линии, у горизонтальной стрелки прямоугольник жеста вырождён
    в отрезок, и на слой ложилась стрелка с обрубленным наконечником при целом превью.
    Опорные точки кривых сердца тоже стоят за прямоугольником жеста.
37. **Превью показывается тем же режимом, каким ляжет на слой** —
    `ITool.PreviewBlendMode` идёт в `Document.Render` рядом с самим битмапом. Ластик на
    верхнем слое пиксели вычитает (`DstOut`), и превью, нарисованное обычным source-over,
    вело белую полосу там, где получится дыра: картинка менялась на отпускании, когда
    рука уже отведена. Вычитание при этом обязано быть заперто в своём слое — отдельным
    `SaveLayer`, — иначе оно снимает и всё, что уже сложено ниже, и ластик на верхнем
    слое пробивает документ до самой бумаги. Прозрачность слоя тогда уходит в краску
    группы: применить её и к слою, и к группе значило бы возвести в квадрат.
38. **Размеры интерфейса меряются в экранных пикселях, а не в пикселях холста** — зона
    хвата угловой точки (`QuadTool`, через `ToolContext.Zoom` и `ToDocument`) и отступ
    ручки поворота (`CanvasView.AddRotateHandle`). Сами ручки рисуются фиксированного
    размера на экране, и всё, что должно с ними совпадать, обязано считаться так же:
    иначе на масштабе 0.25 в зону хвата шириной «десять пикселей холста» нельзя попасть
    вовсе (это два экранных), а на масштабе 4 она накрывает сорок экранных и перехватывает
    перетаскивание объекта. Совпадает это только при масштабе 1:1 — там же, где такую
    ошибку и не видно. Экранная величина при этом обязана считаться с размером фигуры, к
    которой её прикладывают: хват углов ограничен половиной меньшей стороны габарита
    (`PickupOps.HitCorner`), иначе на выделении в двадцать пикселей четыре круга радиусом
    десять смыкаются в середине и накрывают его целиком — ни поднять, ни потащить.
39. **Плавающий объект не переживает замену всех слоёв** — `Document.DropFloating` внутри
    `ReplaceAllLayersCommand` и `ResizeCanvasCommand`, там же и по той же причине, что и
    снятие рамки (инвариант 21). Возвращать поднятые пиксели после такой операции некуда:
    слои заменены, а координаты объекта указывают на прежний размер холста. Прижать его —
    дело того, кто затевает операцию, и ДО неё, пока холст ещё прежний: так делают поворот,
    отражение, смена размера, открытие файла и (с 1.13.0) кадрирование, которое раньше
    теряло объект молча.
40. **Объект двигается целиком, вместе со своей маской** — `PickupOps.Translate`, один
    на «Выделение» и «Четырёхугольник». Разными инструментами один и тот же объект
    таскать можно: хоткей поворота поднимает многоугольник, не трогая активный
    инструмент. Пока сдвиг был написан в каждом инструменте свой, «Выделение» двигало
    один габарит — маска оставалась на месте и срезала объект на ходу, до полного
    исчезновения.

41. **Поднятый объект принадлежит документу, а не инструменту** — `OnDeactivate`
    сбрасывает только собственное состояние жеста, а прижимает объект
    `MainViewModel.OnActiveToolChanged`, и только когда новый инструмент с ним работать
    не умеет. «Выделение» и «Четырёхугольник» — две руки для одного и того же: первое
    двигает и масштабирует, второй вдобавок тянет углы маски. Пока каждый прижимал объект
    у себя, инструмент решал за того, о ком ничего не знает — на какой его меняют, — и
    нажатие Q по перетащенному выделению прибивало его к холсту раньше, чем пользователь
    успевал взяться за угол. В Electron то же исключение записано прямо в обработчике
    кнопок инструментов. По той же причине «снять выделение» (Ctrl+D) объект прижимает, а
    не оставляет висеть: подъём забирает рамку себе, и проверка на одну только рамку
    отправляла команду в никуда.
42. **Снимок для отмены шире того, что нарисовано, на кромку сглаживания** — область
    подъёма (`Document.SourceRect`) и область стирания многоугольника
    (`EraseRegionCommand`) раздвигаются на пиксель со всех сторон. Контур идёт по дробным
    координатам, сглаживание задевает пиксели за габаритом, округлённым к ближайшему
    целому, и отмена возвращала не всё: по краю оставалась бледная кайма из пикселей,
    которые стёрли, но не записали. У прямоугольника такой поправки не нужно — он рисуется
    по целым числам и за них не выходит.
43. **Текст рисуется построчно** — `SKCanvas.DrawText` кладёт ОДИН ряд глифов и перевода
    строки не знает: «
» уходит в шрифт наравне с буквами и выходит прямоугольником-
    заглушкой, а всё, что за ним, ложится той же строкой дальше вправо. Многострочное
    попадает в поле вставкой из буфера обмена. Межстрочный интервал берётся у самого
    шрифта (`SKPaint.FontSpacing`), а не выдумывается: у разных гарнитур высота строки
    разная.
44. **Координата пикселя округляется вниз, а не в сторону нуля** — приведение `float` к
    `int` схлопывает в ноль всё от −0.99 до 0, и точка чуть левее или выше холста
    становится его левым верхним пикселем. Заливка и пипетка считают через `MathF.Floor`.
45. **«Есть ли что обрабатывать» спрашивают про площадь, а не про `IsEmpty`** —
    `GeometryMath.HasArea`. `SKRectI.IsEmpty` в SkiaSharp отвечает true только на
    прямоугольник из четырёх нулей, а полоска нулевой ширины для него непустая. Такие
    полоски выходят из любого пересечения с холстом, когда фигура стоит вплотную к его
    краю, и дальше из них строится `SKBitmap` нулевого размера — на нём
    `SKImage.FromBitmap` возвращает null, и подъём выделения у края холста ронял
    приложение. Проверок в коде дюжина, и ошибиться достаточно в одной.
46. **Нижний слой удалить нельзя: он бумага документа** — `MainViewModel.RemoveLayer`.
    На «слой ноль — это бумага» держатся `PickupOps.EraseColor`, `StrokeToolBase.OnBottomLayer`,
    `ResizeCanvasCommand.Rebuild`, `ClearCanvasCommand` и кеинг при подъёме (инвариант 35).
    Пока бумагу можно было удалить, ею молча становился следующий слой — со всеми этими
    правилами разом: прозрачный слой после первой же смены размера холста оказывался залит
    белым, а ластик переставал стирать и начинал красить.
47. **Запись, от которой отказались, а отменить по порядку нельзя, вычёркивается** —
    `HistoryManager.Forget`. Пикап вставки снимает сама вставка (инвариант 34), но
    отменить её можно, только пока она последняя, а между ней и отказом легко ложится
    другая правка. Отступиться тут нельзя: пикап всё равно снимут, и получится ровно то,
    от чего инвариант 34 и написан. Вычёркивать вправе только запись, не тронувшую ни
    одного пикселя, — иначе её пиксели остались бы без возможности отмены.
48. **Запись описывает состояние документа, а не только его пиксели** — прижатие
    поднятого объекта пишется `RegionDiffCommand` с `dropsFloating`, и при повторе она
    и рисует пиксели, и снимает объект. Ленту проигрывает не только Ctrl+Y, но и клик по
    строке в панели истории: вставка при повторе кладёт картинку в руки заново, и без
    этого поверх прижатой картинки оставалась её же копия. По той же причине
    `CommitFloating` во время прогулки по ленте ничего не рисует, а снимает объект:
    `Push` в этот момент молчит (инвариант 10), и нарисованное осталось бы на холсте
    вовсе без записи о себе.
49. **Копируется то, что выделено, а не то, что под ним** — `ClipboardService.ExtractForClipboard`.
    У рамки выделено содержимое прямоугольника, и копируется сборка всех слоёв
    (инвариант 14). У поднятого объекта выделен он сам: копия рисуется в чистый битмап
    одним `Document.DrawPickup`, на прозрачном фоне. Пока и объект шёл через общую сборку
    по своему габариту, уведённый на цветное место он попадал в буфер вместе с этим цветом
    прямоугольной заплаткой — а габарит повёрнутого объекта заметно шире его самого.
    Когда копировать нечего (рамка или объект целиком за холстом), метод отвечает `null`,
    а не битмапом 1×1: тот честно уходил в буфер вместо того, что там лежало.
50. **Shift у ручек — пропорции и ровный угол** — `GeometryMath.ResizeRotated(keepAspect)`
    и `GeometryMath.SnapAngle`. Обе вещи есть в Electron-версии с самого начала. Без них
    масштабировать картинку, не расплющив её, было нельзя вовсе, а поставить поворот ровно
    на 90° или 45° — только случайно: хоткеи «[» и «]» дают ровный шаг, но крутят от
    текущего положения, а не приводят к нему.
51. **Снимок пикапа относится только к слою, с которого его сняли** — `Document.SnapshotLayer`.
    Слой могли удалить, пока объект в руках; рисовать прижатое в активный слой при этом
    можно и нужно (иначе теряются сами пиксели), а вот описывать по чужому снимку
    ПРЕЖНЕЕ состояние нельзя ничем. Пока запасной вариант стоял в обоих местах разом,
    Escape стирал по чужому слою рисунок целиком, Delete записывал дыру не там, где надо,
    а первый Ctrl+Z после прижатия вписывал в него пиксели удалённого слоя. Ленивое
    стирание (`PickupOps.EnsureLazyErase`) ищет слой строго по идентификатору по той же
    причине.
52. **Жест ложится на тот слой, на котором начался** — инструменты снимают слой на
    нажатии и передают его в `DrawStrokeCommand`. Команда исполняется на отпускании, и
    «какой слой активен сейчас» — правильный ответ только в момент нажатия: у окна ввода
    текста между кликом и OK проходит сколько угодно времени. Ластику это стоит не только
    слоя, но и режима слияния — на нижнем слое он красит белым, на верхних вычитает
    пиксели, — поэтому режим тоже снимается на нажатии, а не пересчитывается на отпускании.
53. **Растянутый или повёрнутый объект пересэмплируется с фильтрацией** —
    `Document.DrawPickup` ставит `SKFilterQuality.Medium`, когда габарит не совпадает с
    размером битмапа или есть поворот. Без неё Skia берёт ближайший пиксель: уменьшенная
    вдвое фотография теряет каждую вторую строку. При размере один к одному и без
    поворота фильтрации быть не должно — пиксельный рисунок обязан переезжать без
    размытия. Сборка на экране и в слое общая, поэтому правило одно на оба случая.
54. **Прижатие, не изменившее ни пикселя, забирает с собой вставку** — `Document.CommitFloating`
    зовёт `HistoryManager.Forget` для записи-владельца, если записывать оказалось нечего.
    Так бывает, когда картинку уносят за край холста: класть её некуда, а запись «Вставка»
    оставалась в ленте применённой — история расходилась с холстом, и прогулка по ней
    создавала картинку заново, из ниоткуда. То же правило, по которому от вставки
    отказываются Escape и Delete (инвариант 47).
55. **«Создать» и «Открыть» возвращают слой целиком, а не только его пиксели** — имя,
    видимость и прозрачность выправляются вместе с содержимым (`ClearCanvasCommand`,
    `DocumentTransform.OpenImage` через `ReplaceAllLayersCommand.LayerProps`). Иначе новый
    документ приезжает с настройками прошлой работы: рисуешь по чистому листу и не видишь
    ни штриха, а открытая фотография ложится в спрятанный слой. Отмена возвращает прежние
    настройки. Поворота и отражения это не касается: они про пиксели.
56. **Замену документа предваряет прижатие поднятого объекта** — как у поворота,
    отражения, кадрирования и смены размера. `ClearCanvasCommand` объект только снимает,
    и вставленная картинка, которую пользователь ещё держал в руках, исчезала бесследно:
    отмена «Создать» возвращала слои, но не её.
57. **Новый плавающий объект прижимает прежний** — правило живёт в сеттере
    `Document.FloatingPickup`, рядом с тем, по которому рамка выделения прижимает объект.
    Пока его знали только вызывающие, достаточно было одного пути мимо них: ссылка
    менялась, пиксели прежнего объекта не ложились ни на один слой, его битмапы не
    освобождались вовсе, а запись «Вставка» оставалась в ленте применённой без картинки.
58. **Позиция курсора в ленте однозначно задаёт документ** — каким бы путём до строки ни
    дошли, сверху отменами или снизу повторами, на ней обязан быть один и тот же документ,
    вплоть до того, держит ли пользователь что-то в руках. Проверяет это четвёртый
    инвариант `TimelineFuzzTests`; он же нашёл инвариант 57.
59. **Прогулка по ленте возвращает на место поднятое, но не отнимает вставленное** —
    `HistoryManager.ReleaseUnownedFloating`. Поднятое пользователем выделение держит снимок
    слоя на момент подъёма, и после шага по ленте этот снимок ни к чему не относится. У
    вставки же есть своя запись, и пока она применена, картинка обязана быть в руках: пока
    снималось всё подряд, клик по строке «Вставка» и обычный Ctrl+Y убирали картинку, а
    вернуть её было нечем.
60. **Прижатая вставка — одна запись в ленте, а не две** — `Document.CommitFloating`
    вычёркивает запись-владельца всегда, а не только когда записывать оказалось нечего.
    Всё, что вставка означает для холста, описывает диф прижатия, и подпись «Вставка»
    несёт он же. Пока их было две, один и тот же курсор давал то пустой холст, то картинку
    в руках — и не там, куда её перетащили, а в точке вставки.
61. **Копия выделения повторяет его форму, а не габарит** — `ClipboardService` режет копию
    по многоугольнику. Углы описанного вокруг прямоугольника лежат вне выделенного: Ctrl+C
    по треугольнику клал в буфер заплатку с фоном по углам, при том что Delete по тому же
    выделению стирал именно многоугольник.
62. **«Создать» возвращает и размер холста** — `Document.DefaultWidth/DefaultHeight`,
    `ClearCanvasCommand`. Новый документ — это чистый лист, а не старый со стёртым
    рисунком; габарит прежней работы такая же её часть, как стопка слоёв и имя бумаги
    (инвариант 55). Отмена возвращает и работу, и её размер — слои строятся под
    вернувшийся холст.
63. **Отмена удаления слоя возвращает и активный слой** — `LayerStackCommand` записывает
    его при удалении и читает при отмене. Активным становился восстановленный, и кисть
    после Ctrl+Z оказывалась не там, где рисовала минуту назад. Добавление слоя, наоборот,
    выбирает новый: его для того и заводят.
64. **Заливка сравнивает цвета с допуском и помнит пройденное** — два уровня на канал, как
    `colorsMatch` в Electron-версии. Точное совпадение означало, что по фотографии
    заливается ровно один пиксель. Карта пройденных пикселей идёт с допуском в комплекте:
    без неё залитый пиксель может остаться в пределах допуска от исходного, соседи кладут
    его в стек снова и снова, и программа зависает.
65. **Элемент интерфейса не может быть больше того, за что он держит** — `PickupOps.HitCorner`
    ужимает зону хвата угла до половины меньшей стороны фигуры, `PickupOps.HandleSize` —
    сторону ручки масштабирования. Восемь ручек по двенадцать экранных пикселей у объекта
    меньше 24 пикселей на экране смыкаются и накрывают его целиком: клик в любую точку
    попадает в ручку, и объект нельзя ни потащить, ни увезти. Правило одно на оба места и
    по одной причине.
66. **Габарит открываемой картинки проверяется по заголовку файла** — `FileService.IsOpenable`
    через `SKCodec`, до раскодирования, теми же границами, что держит диалог смены размера
    (`ResizeCanvasCommand.IsAllowed`). Раскодировать сначала и посмотреть потом нельзя:
    снимок 25000×25000 падает нехваткой памяти мимо всех `catch`'ей и уносит несохранённый
    рисунок вместе с приложением.
67. **Вставка ложится так, чтобы её было видно** — `MainViewModel.PasteOrigin`. Отступ в
    двадцать пикселей от угла не должен уносить картинку с холста: на холсте меньше
    двадцати пикселей вставка оказывалась целиком за краем, и Ctrl+V не показывал ничего.
68. **Жест, который отказал, объясняет себя строкой в статусбаре** — скрытый слой, нулевая
    прозрачность инструмента и слоя, бумага и единственный слой, которые нельзя удалить,
    занятый и пустой буфер обмена, рамка меньше четырёх пикселей и кадрирование по такой
    же рамке, Ctrl+X без выделения и хоткеи поворота без него же. Молчащий отказ неотличим от
    сломанной программы. Чистый клик при этом молчит: им снимают выделение, а не
    промахиваются.
69. **Запись описывает состояние на момент записи, а не на момент начала жеста** — «до» для
    дифа прижатия собирается из живого слоя, в котором восстановлена одна только исходная
    область (`Document.BeforeCommit`), а снимок слоя пересматривается прямо перед тем, как
    эту область выкусить (`PickupOps.EnsureLazyErase`). Снимок на момент подъёма описывает
    слой до всего, что могло случиться с ним потом, и откатывал бы это заодно.
70. **Строка ленты не обещает того, чего лента не может** — `HistoryManager.Trimmed`. Когда
    самые старые записи выброшены переполнением, нулевая позиция это уже не чистый лист, и
    строка «Исходное состояние» называется в панели иначе.
71. **Правка, не изменившая ни пикселя, в ленту не попадает** — вопрос задаёт сама лента
    (`HistoryManager.ExecuteAndPush` через `IDocumentCommand.ChangedAnything`), а не каждая
    команда у своего вызывающего. Отвечают на него штрих (`DrawStrokeCommand` сравнивает
    область до и после), операции над всем документом (`ReplaceAllLayersCommand` сравнивает
    размер холста, пиксели и свойства слоёв), заливка и стирание выделения. Пустая запись
    включает признак несохранённой работы, и приложение спрашивает про сохранение после
    жеста, которого на экране не было видно: ластик по чистой бумаге, белым по белому,
    штрих мимо холста, кадрирование по всему холсту, отражение симметричной картинки.
72. **Строка ленты означает одно и то же состояние, откуда бы на неё ни пришли** —
    `HistoryManager.JumpTo` снимает с рук поднятое ДО проверки «идти некуда». Щелчок по
    текущей строке возвращался сразу, и на одной позиции получалось то с картинкой в
    руках, то без. Проверяет это инвариант 58, но фаззер ходит между разными позициями и
    мимо этой развилки проскакивал.
73. **Слоя, которого не видно, в картинке нет, а объект в руках виден всегда** —
    `Document.Render` и `Document.SampleComposite`. «Не видно» это и снятая галочка, и
    прозрачность, выкрученная в ноль: Skia на краске с нулевой альфой подмешивает битмап
    примерно на уровень из 255, и погашенный слой подкрашивал и экран, и файл. Плавающий
    объект — наоборот: и то и другое его не касается (`Document.PickupOpacity`), спрятать
    то, что пользователь сейчас тащит, хуже любой нестыковки.

### Работа с пикселями напрямую

`SKBitmap.GetPixel`/`SetPixel` пересекают managed/native границу на каждый вызов.
Для попиксельных проходов это доминирующая стоимость: заливка холста 900×600 через
них занимала около 700 мс. `FillCommand` вместо этого копирует сырой BGRA-буфер
через `Marshal.Copy`, работает с `byte[]` и копирует обратно — те же 900×600
укладываются в 25 мс, 4000×3000 в 172 мс.

Буфер премультиплицированный (`Bgra8888`/`Premul`), поэтому цвет заливки нужно
премультиплицировать вручную: `SetPixel` делал это за нас. После записи в нативную
память обязателен `NotifyPixelsChanged()`, иначе Skia может отдать закешированное.

### Форматы файлов

Skia умеет **кодировать только PNG / JPEG / WebP** — `SKImage.Encode` для BMP и GIF
возвращает `null`. Поэтому диалог «Сохранить как» предлагает только эти три, а если
целью оказался другой контейнер (например, открыли `.gif` и нажали Ctrl+S), файл
пишется рядом как `.png` с предупреждением. Открывать при этом можно всё, что
Skia декодирует, включая BMP и GIF.

Запись идёт через `File.Create`, а не `File.OpenWrite`: второй не обрезает файл, и
меньшая картинка поверх большей оставляла бы хвост предыдущей.

### Добавить новый tool

1. Реализовать `ITool` в `Tools/MyTool.cs`.
2. Добавить значение в `ToolKind` enum.
3. Зарегистрировать в `MainViewModel._tools`.
4. Добавить `ToggleButton` в `MainWindow.xaml` (левая панель) + опционально `KeyBinding`.

Всё. Никаких изменений в Document, History, или CanvasView не требуется.

### Выделения

- **Select (S)** — растянуть прямоугольник, клик внутри поднимает пиксели в
  `FloatingPickup`, дальше 8 ручек масштаба и ручка поворота.
- **Quad (Q)** — то же для четырёхугольника. Углы помечены точками и тянутся по
  отдельности: это меняет форму клипа, содержимое не деформируется. Клик внутри
  полигона поднимает пиксели, дальше пикап двигается, масштабируется и вращается
  как прямоугольный. Перетаскивание угла намеренно **не** запускает ленивое
  стирание — исходные пиксели остаются на месте, пока пикап не сдвинут.
- Переход между **S** и **Q** объект не прижимает: это две руки для одного и того же,
  и «выдели прямоугольником — искриви углы» работает как один жест. Прижимает его
  переход на любой другой инструмент, «снять выделение» (Ctrl+D) и Enter; Escape
  возвращает пиксели на место.
- Зона хвата угловой точки ограничена половиной меньшей стороны выделения: на мелких
  фигурах середина остаётся телу, иначе четыре угла накрывали бы её целиком.
- **Shift** у угловой ручки держит пропорции, у ручки поворота ставит угол на ровные 15°.
  Боковые ручки меняют одну сторону по определению — Shift их не касается.
- Ctrl+C по поднятому объекту кладёт в буфер его самого, на прозрачном фоне; Ctrl+C по
  рамке — то, что видно внутри неё, сборкой всех слоёв. Если копировать нечего (объект
  или рамка целиком за холстом), Ctrl+C отказывает и говорит об этом, а Ctrl+X при этом
  ничего не вырезает.
- Растянутый или повёрнутый объект прижимается со сглаживанием, один к одному — без:
  фотографию не хочется получать лесенкой, а пиксельный рисунок — размытым.
- Слой, с которого объект подняли, помнится по идентификатору. Его можно удалить, пока
  объект в руках: прижмётся он тогда в активный слой, а вернуть исходные пиксели уже
  нечем — их забрало удаление слоя, и возвращает их его отмена.
- Белый фон вычитается при подъёме прямоугольника с нижнего слоя (`BitmapKeying`),
  чтобы выделение не тащило за собой непрозрачный белый прямоугольник. У
  многоугольника форму задаёт его маска, а на верхних слоях фон и так прозрачный —
  там вычитать нечего, и попытка выкусывала бы нарисованное белым.

Флажок **«Заливать фигуры»** в правой панели переключает прямоугольник, эллипс,
треугольник, звезду и сердце между контуром и заливкой.
