## Что это

Один файл `paint-pro.html` на 280 КБ держит весь редактор: разметку, стили и код, снаружи не подгружается ничего. Из него собирается три вещи, и это одна и та же программа.

| Сборка | Что это | Вес |
| --- | --- | --- |
| Установщик | NSIS, ставится как «Paint Pro Electron» в свою папку, с ассоциациями файлов | 74,6 МБ |
| Portable | один `.exe`, ничего устанавливать не надо | 74,4 МБ |
| Браузерная | один `.html`, открывается двойным щелчком, работает без сети | 274 КБ |

Настольные сборки несут в себе целый Chromium - отсюда 74 МБ против 274 КБ у той же программы в браузере. Это честная плата за нативное меню, настоящий диалог сохранения и ассоциации файлов.

Electron добавляет ровно четыре вещи: окно, нативное меню, диалоги открытия и сохранения, перетаскивание картинок в окно. Всё остальное - рисование, лента истории, слои, выделение - обычный код по canvas, который без изменений работает во вкладке браузера. Перед каждым нативным вызовом проверяется мост `window.electronAPI`, поэтому в браузере файл теряет возможности, а не ломается.

## Что умеет

Девятнадцать инструментов, пять тем, слои и лента истории, которую можно править.

| Группа | Инструменты |
| --- | --- |
| От руки | карандаш, кисть, маркер, ластик |
| Цвет | заливка, пипетка |
| Текст | текст со шрифтом и размером |
| Фигуры | линия, прямоугольник, эллипс, треугольник, прямоугольный треугольник, звезда, стрелка, сердце |
| Выделение | прямоугольное выделение, полигон по 4 точкам, обрезка |
| Просмотр | рука (панорама), масштаб 10-800 % |

Сверх списка инструментов:

- **Слои.** Добавить, удалить, переставить, скрыть, задать прозрачность. Рисование идёт в активный слой, картинка собирается из стопки, и одна и та же сборка кормит экран и сохраняемый файл.
- **Лента истории, где правку можно выключить.** Не только отмена и повтор: любую отдельную запись в середине ленты можно выключить, и документ пересобирается без неё, а всё, что было после, остаётся на месте. Включение обратно возвращает документ до пикселя.
- **Поднятый объект.** Выделите область и щёлкните внутрь - пиксели отрываются от бумаги: их можно тащить, тянуть за восемь ручек, вращать клавишами `[` и `]`. `Enter` кладёт на место, `Escape` отменяет подъём.
- **Пять тем** в меню «Вид → Тема», выбор запоминается. Холст темам не подчиняется: бумага белая всегда, потому что тема, перекрашивающая рисунок, - это не тема.
- **Одна раскладка с C#-версией.** Инструменты слева с подписями, справа цвет, последние
  цвета, размер, прозрачность, холст, быстрые действия, слои и история. Обе боковые
  панели тянутся за край, ширина и место окна запоминаются.
- **Отказы, которые говорят.** Каждое действие, которое законно ничего не делает, пишет об этом в строку состояния, а не проглатывает щелчок.

| Клавиши | Действие | | Клавиша | Инструмент |

| `Ctrl+S` | сохранить | | `G` | заливка |
| `Ctrl+Shift+S` | сохранить как | | `I` | пипетка |

Колесо мыши над холстом меняет размер текущего инструмента и говорит, когда упёрлось в предел. С зажатым `Ctrl` - меняет масштаб. Вне холста и у инструментов без размера прокручивает вид, как обычно.

## Сборка и запуск

Node.js 18 или новее. Первый `npm install` тянет Electron, это около 150 МБ.

```bash
npm install
npm start                 # запуск в режиме разработки
npm test                  # 469 проверок в Chromium, ~4 минуты
npm run test:app          # 14 проверок по настоящему приложению, ~40 секунд
npm run build:web         # один файл для браузера, кладётся в dist/
npm run build             # portable .exe
npm run build-installer   # установщик NSIS
npm run screenshots       # перерисовать все картинки этого файла
```

Для `npm test` один раз нужен браузер: `npx playwright install chromium`.

Номер версии живёт ровно в одном месте - в поле `version` файла `package.json`. Оттуда его читают окно, окно «О программе», имена собранных файлов и браузерная сборка.

## Про проверки

469 проверок на Playwright плюс 17 по собранному приложению. Это не юнит-тесты вокруг функций: страница открывается в Chromium, мышь по-настоящему водит по холсту, а утверждения читают пиксели через `getImageData` или сравнивают целые кадры через `toDataURL`. Подменяется только мост в Electron. Медленные семнадцать запускают настоящий Electron и выполняют код в main-процессе, подменяя нативные диалоги: запись файла и вопрос при закрытии живут именно там, и больше туда ничто не достаёт.

Два файла - не примеры, а фаззеры. `fuzz.spec.js` порождает из seed'а случайные последовательности правок и проверяет на них четыре инварианта ленты истории; сильнейший звучит так: *позиция курсора однозначно задаёт документ, каким бы путём до неё ни дошли*. Один этот закон накрывает больше, чем любой список руками написанных случаев про отмену.

Это не вкусовщина, а вывод по тому, откуда брались дефекты:

| Выпуск | Чем найдено | Что это было |
| --- | --- | --- |
| 1.11.2 | первым же прогоном проверок | три сломанных поведения, которых никто не замечал |
| 1.11.3 | сплошным проходом по тупиковым действиям | 11 мест отказывали молча, теперь объясняют причину |
| 1.11.5 | сравнением двух путей одного действия | вставка шла двумя путями, а отступ был поправлен в одном |
| 1.12.1 | сплошным проходом по новой площади слоёв | семь дефектов за один заход |
| 1.15.0 | вопросом «чем вообще кончается жест мышью» | ресайз выделения срывался, стоило отклониться на два пикселя |
| 1.16.0 | проверкой раскладки на настоящем окне | на русской раскладке не работали горячие клавиши; кнопки в суженной панели вылезали под полосу прокрутки |
| 1.16.1 | оповещениями Dependabot на GitHub | приложение работало на Electron 33 с 32 известными уязвимостями движка; теперь Electron 44 |
| 1.17.0 | замечанием пользователя | колесо меняло размер кисти только после того, как отпустишь кнопку и нажмёшь снова; ластик с размером, изменённым посреди штриха, повторялся одним размером |
| 1.18.0 | замечанием пользователя | кружок размера был курсором-картинкой с потолком в 96 точек - треть кисти на 300 px; карандаш рисовал половиной размера, маркер - в полтора раза толще |
| 1.19.0 | замечанием пользователя | кружок размера отставал от крестика на кадр; выделенный объект замирал там, где указатель ушёл с холста; кисть рисовала ровно то же, что карандаш |
| 1.20.0 | замечанием пользователя | Ctrl+P печатал всё окно с меню и панелями вместо картинки |

Последний - самый наглядный ответ на вопрос, почему чтение исходников такого не находит. Рамка выделения и её восемь ручек лежат поверх холста отдельными элементами, а не внутри него, поэтому курсор, заехавший на ручку, поднимает то же событие «курсор ушёл», что и уход за край холста, - а на нём висело завершение жеста. Пока ведёшь мышь идеально по траектории, ручка едет ровно под курсором и баг не виден. Теперь жест кончается отпусканием кнопки, а мазок, ушедший за край холста, продолжается при возврате.

## Скриншоты не снимают руками

`npm run screenshots` поднимает настоящее приложение через Playwright, рисует настоящей мышью тот самый пейзаж, что выше, проходит по всем пяти темам и складывает картинки в `docs/screenshots/`. Картинки в документации гниют быстрее текста, и заметить это некому; так они всегда в одной команде от того, чтобы снова стать правдой. Скрипт - [`tools/make-screenshots.js`](tools/make-screenshots.js).

## Откуда это взялось

У Paint Pro есть близнец: тот же редактор, переписанный на C# 12 с WPF и SkiaSharp. Обе версии развиваются рядом, и большая часть правил этого кода найдена на одной стороне и перенесена на другую - `tests/parity.spec.js` назван ровно про это, каждая проверка там подписана выпуском, в котором правило появилось у соседа. C#-версия лежит в том же репозитории: [её README](../docs/CSHARP.ru.md) и [README репозитория](../README.ru.md).
